* First vertical slice

This slice adds immutable session capability routes for web, browser, and
terminal selection. Route choices live in each launcher's runtime
configuration and version-two recovery-session record. Version-one records
remain readable and preserve the defaults.

Only the web route has an executor in this slice. An explicit =:nous= route
changes both the provider-visible =web.run= schema and execution credentials to
Nous managed Firecrawl while inference can remain Codex. The default
=:inference= route retains prior behavior. There is no silent fallback.

* Managed Modal vertical slice

The Modal implementation follows =tools/environments/managed_modal.py= and
=modal_utils.py= from the inspected checkout. It uses bearer-plus-JSON requests
to the dedicated Modal gateway, creates one lazy persistent sandbox per agent,
starts execs, polls terminal states, cancels timed-out or interrupted execs, and
terminates with =snapshotBeforeTerminate=true=. The client adds no file API
because the inspected contract has none.

=shell.run= performs the existing command permission decision before dispatching
to the selected explicit local or managed Modal backend. Modal never falls back
to local execution. It forwards no process environment, host credentials,
secrets, or workspace files. Absolute command directories under the Modal route
are remote paths.

Each launcher derives an opaque stable logical key from its private recovery
pointer. Task children inherit the =:modal= route but receive keys from their
unique task execution identifiers, so concurrent agents do not share sandboxes.
The status views expose logical identity, local lifecycle state, and live
sandbox identifier without creating a sandbox.

* Managed browser vertical slice

The browser implementation follows
=plugins/browser/browser_use/provider.py= from the same inspected commit. It
creates =POST /browsers= with ={timeout:5, proxyCountryCode:"us"}=,
=X-Browser-Use-API-Key=, and a retry-stable =X-Idempotency-Key=. The create key
is retained after transport failures, 5xx responses, and 409 responses whose
structured error says the request is already in progress. Successful responses
must contain =id= and a nonempty =cdpUrl= or =connectUrl=. Cleanup sends
=PATCH /browsers/<id>= with ={action:"stop"}=.

Actions use the returned CDP WebSocket through the locked
=websocket-driver-client= dependency. The client bounds messages, correlates
request IDs, retains a bounded event queue, routes flattened target sessions,
and reports close, protocol, command, and timeout failures without fallback.
The accessibility snapshot creates refs that are valid only for its generation.
Navigation validates public HTTP(S) destinations. Screenshots pass through the
existing private image attachment pipeline.

The =browser= namespace is registered only for =:nous= sessions. Every action
uses ordinary external-tool authorization under its own canonical identity.
Typed text is not echoed and uses next-response-only conversation persistence.
Each agent owns its lazy runtime; permitted task children inherit the route but
receive unique logical identities and sessions. Agent shutdown stops the
remote session, while status and info inspect lifecycle and session identity
without creating one.

* Managed browser network trust boundary

Autolith intercepts every CDP request URL pattern. HTTP(S) and WS(S)
destinations use the literal-address, hostname, and local-DNS policy, with
WS(S) normalized only for validation. CDP-presented =data:=, =blob:=, and
=about:= requests are the explicit non-network allowlist; unsupported schemes
fail. Redirect and subresource checks remain defense in depth, not an
end-to-end SSRF boundary. The remote Browser Use environment can resolve a
hostname differently from the local Autolith host, while the inspected managed
gateway contract exposes no destination-pinning or network-policy endpoint.
Same-network enforcement is therefore a Browser Use/Nous gateway trust
requirement. Autolith cannot claim an SSRF boundary across differing local and
remote DNS views.

Mocked lifecycle and CDP tests cover retry idempotency, headers and payloads,
correlation, events, all-pattern interception, HTTP(S) and WS(S) destination
policy, explicit non-network schemes, unsupported schemes, practical action
commands, schema gating, denial before creation, child isolation, cleanup,
stale refs, screenshots, status, and message bounds.
